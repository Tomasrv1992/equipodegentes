## 1. ¿Qué hace el agente?

**Equipo-facturacion** es un pipeline automatizado de cuentas por pagar para clínicas y empresas colombianas. Corre 1 vez por día (cron 7:00 AM Bogotá) y procesa los emails de la bandeja de Gmail del cliente.

### Flujo end-to-end por email

```
Gmail (entrada)
   ↓ búsqueda: emails con adjuntos (ZIP/PDF/DOCX) del año actual
   ↓ filtro: -label:Facturas/YYYY -label:Descartado/YYYY -label:Procesado
   ↓
Pipeline (clasificador)
   ├─ ZIP DIAN → parseInvoiceXml → factura electrónica
   ├─ PDF planilla SS → numero titular vs NIT cliente → procesa o skip tercero
   ├─ DOCX → LLM Claude extrae datos → cuenta de cobro
   └─ PDF genérico → LLM Claude → recibo internacional / servicio local
   ↓
Validaciones
   ├─ Pre-filtros (sender, subject, indicadores de factura)
   ├─ esNumeroFacturaValido, esFechaFacturaValida, esNitValido
   ├─ isDuplicate (numero + nit + proveedor)
   └─ Retenciones (RTF/IVA/ICA según reglas cliente)
   ↓
Salida exitosa:
   ├─ Drive: {numeroDIAN}. {Proveedor}.pdf en carpeta YYYY-MM/
   ├─ Sheet: fila en pestaña del mes (Enero, Febrero, ...)
   ├─ Gmail: label Facturas/YYYY + archivar (remover INBOX)
   └─ BD: event agent_events tipo=factura_procesada
   ↓
Salida descarte:
   ├─ Gmail: label Descartado/YYYY + archivar
   └─ BD: event agent_events tipo=email_descartado con motivo específico
```

### Motivos de descarte trackeados

Cada descarte registra su motivo en BD (pestaña "Descartes" del Sheet replica la info):

- `dup-en-sheet` / `dup-guard-emergencia` — ya existe en Sheet
- `planilla-ss-tercero` — planilla SS de freelancer (titular ≠ NIT cliente)
- `no-es-factura-dian` — XML tipoDoc 05/07/91/92 (notas crédito/débito/retenciones)
- `pdf-no-es-factura` / `docx-no-es-factura` — LLM clasificó como no-factura
- `pre-filter-sender` / `pre-filter-subject` — heurística rechazó antes de LLM
- `factura-invalida` / `docx-invalida` / `pdf-invalido` — numero/fecha/NIT malformado
- `self-emitted` — cliente es el emisor (auto-factura)
- `fecha-año-anterior` — factura de año previo
- `pdf-encrypted` / `pdf-sin-texto` / `zip-sin-xml` — no procesable

## 2. Arquitectura técnica

### Stack
- **TypeScript** en Node.js 20+
- **Netlify Functions** (cron + background, 15min timeout máximo)
- **Supabase Postgres** + pgcrypto (multi-tenant, OAuth tokens cifrados)
- **Google APIs:** Gmail, Drive, Sheets vía googleapis
- **Anthropic Claude Haiku 4.5** para extracción no-DIAN
- **Resend** para emails al cliente

### Sistema multi-tenant

- Tabla `clientes` (Supabase) con `slug` + `nombre`
- Tabla `client_credentials` con OAuth tokens cifrados (pgcrypto) por cliente
- Cada cron itera todos los clientes activos y dispatch 1 background por cliente con stagger 800ms (para no triggerear invalid_grant)
- Lock atómico `dispatch_locks` con TTL 15min previene runs duplicados

3. **Pipeline serial (concurrency=1 default).** Para evitar quota Sheets API y race conditions.
4. **isDuplicate por (numero, nit, proveedor).** No depende de consecutivos.

## I) Workflow incidentes comunes

### Cron caído (sin créditos Netlify)
- Síntoma: no aparecen runs en `inspect-runs` por varios días
- Fix: recargar Netlify
- Recovery: el cron del día siguiente procesa todo el acumulado (con `force=false` el query incluye los emails sin label)

### OAuth expirado de un cliente
- Síntoma: preflight fail `invalid_grant` → marca `oauth_status='expired'`
- Fix: cliente reconecta vía panel admin (mismo flow de onboarding)

### Sheet con duplicación masiva
- Causa histórica: cache de `loadSheetRows` cacheaba `[]` cuando había timeout (BUG H)
- Fix actual: si lectura falla con error no-tab-not-found → throw (aborta cliente, no contamina cache)
- Recovery: endpoint `rebuild-sheet-from-events-background` reconstruye desde `agent_events.factura_procesada`

### Facturas válidas se descartan (falsos positivos LLM)
- Síntoma: aparecen en `Descartado/2026` siendo facturas reales
- Diagnóstico: abrir email, mirar labels que tiene + buscar en Sheet por numero
- Fix: si el motivo es `pdf-no-es-factura`, ajustar pre-filters o agregar a categoría confiable en `categorizacion-reglas.json`
